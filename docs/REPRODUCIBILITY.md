# Reproduction boundary

Public execution has two paths: fabricated-data software tests, and deterministic display rendering from approved aggregate source data. Install requirements-display.txt for plotting and requirements-test.txt for tests. The release audit records actual test counts and the tested environment; no historical test count is a current guarantee.

The manuscript source CSVs retain their existing numeric strings. Final Figure 1–5 PDFs/SVGs/PNGs are copied from the final display lock. Rendering adapts only filesystem/argument plumbing and preserves the executed display geometry and encodings. SVG/PDF metadata or generated object identifiers can differ across runs; graphical values and source reconciliation remain authoritative.

Current scientific kernels preserve likelihoods, optimizer starts/bounds/tolerances, decision thresholds, variance standardization and deterministic stream derivation. Input/output paths and imports are adapted. The fixed random-stream namespace is retained as a reproducibility constant; it is not a release-history statement.

Known-truth simulation requires empirical calibration templates and sampling covariance interfaces from an authorized reconstruction; those restricted hospital-level inputs are not included. The public release does not promise exact reproduction of all historical clinical extraction, splits, predictions or model training. Bootstrap predictive mixtures condition on supplied estimated sampling covariance and do not propagate uncertainty in that covariance itself.

The four tolerances and multiple DGPs are distinct related scenarios. No composite scientific success rule, strategy optimization or calibration certification is supplied.
